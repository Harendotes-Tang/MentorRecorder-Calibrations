# MentorRecorder 共享校准

这个仓库存放「导随记录器」（MentorRecorder）玩家分享的**共享校准码**。

游戏每次更新都可能重排报文编号（opcode）。同一区服、同一客户端版本的编号编译在客户端里，对所有玩家都一样，
所以一个玩家在软件里校准成功后，可以把结果分享出来，其他玩家的软件就不必每人再校准一遍。

## 软件怎么使用这个仓库

- **只读下载。** 游戏更新后本机没有可用档案时，软件读取 `index.json`，再按提交号下载同一区服、同一客户端版本的校准码文件。
  软件不向这里上传任何东西。
- **先核实，再使用。** 下载来的校准码不是档案。软件先在玩家自己的本机流量里按结构逐条核实，核实通过才生成档案、开始记录；
  对不上就继续本机校准，已有的校准证据一条都不丢。一份错误的校准码最多让玩家多等一两次登录，不会写出错误的记录。
- **可以关闭。** 这是软件唯一的出站请求；何时发出、带什么、怎样关闭，写在软件的隐私边界说明里。

## 校准码里有什么、没有什么

一份校准码是 `MRC1.` 加上一段压缩后的规范化 JSON。

| 有 | 没有 |
|---|---|
| 格式版本、区服（`CN` / `GLOBAL`）、客户端版本号 | 角色名、服务器、账号、IP 地址 |
| 依据的随包模板编号与模板哈希 | 时间戳、样本数、排过哪些随机任务 |
| 匹配方式，以及这种方式需要的报文长度、字节偏移或状态值 | 说明文字、文件路径、任何报文正文 |
| 学到的几个报文编号（匹配弹窗、换区、副本、职业） | |

校准码的编号 `code_sha256` 是规范化内容的 SHA-256；仓库里的文件名是它的前 12 位。

## 怎样提交

在软件里校准成功、核对过校准时间线之后，点「分享给其他玩家」（需要提供这个按钮的软件版本）。浏览器会打开本仓库预填好的 Issue 页面，
勾选确认后提交即可。GitHub Action 会自动校验、发布，在 Issue 下回复结果并关闭 Issue；正常情况下不需要维护者参与。

没有 GitHub 账号的玩家可以把软件复制出来的校准码交给别人代为提交（按代交者的账号计算下面的规则）。

## 受理规则

- 提交的 GitHub 账号**注册满 30 天**。
- **每个 GitHub 账号，每个区服与客户端版本，只能提交一份校准码。** 再次提交同一份不重复计数；提交另一份会被拒绝。
  按账号的数字编号计算，改名不能多提交一份。
- **不设名额上限。** 不同账号提交完全相同的校准码时合并为一条，`submitters` 记为提交过它的不同账号数。
  软件优先核实提交人数多、发布早的校准码，每个版本最多同时核实 8 份。
- 校准码必须能用 `templates/` 里的随包模板按结构重建。格式错误、模板对不上、结构不合法的一律拒绝，并在 Issue 里说明原因。
- 被拒绝的 Issue 会关闭；修正后请重新提交一个新的 Issue，编辑已经关闭的 Issue 不会被重新处理。

## 撤销

维护者把 `index.json` 里对应条目的 `revoked` 改为 `true`，或者运行：

```bash
python tools/publish.py revoke --repo . --code-sha256 <完整编号>
```

条目不会删除。还没有启用这份校准码的软件读到撤销标记后不再使用它。下载源有缓存：`raw.githubusercontent.com` 几分钟内可见，
jsDelivr 最多约 12 小时（jsDelivr 的缓存不能自助清除，所以 Action 不会尝试清除）。
已经在本机核实并启用的共享档案不会因为索引撤销而联网检查，由软件在本机流量里判出矛盾后撤下。

## 仓库布局

| 路径 | 内容 |
|---|---|
| `index.json` | 已发布校准码的索引，软件下载它（上限 64 KB、512 条） |
| `submissions.json` | 提交台账：哪个账号（数字编号）为哪个版本提交了哪份校准码；软件不下载它 |
| `cn/<客户端版本>/<编号前 12 位>.mrc` | 国服校准码文本，软件按添加它的提交号下载 |
| `global/<客户端版本>/<编号前 12 位>.mrc` | 国际服校准码文本 |
| `templates/<模板编号>.json` | 软件随包模板的逐字节副本，Action 用来按结构重建校验 |
| `tools/` | 校验与发布脚本，从 MentorRecorder 主仓库复制，不在这里手工修改 |
| `.github/ISSUE_TEMPLATE/share-calibration.yml` | 提交表单 |
| `.github/workflows/publish-calibration.yml` | 自动校验、发布、回复；每 30 分钟补处理一次漏掉的提交 |
| `LICENSE.md`、`LICENSES/` | 许可 |

## 数据与隐私

- `submissions.json` 记录提交账号的 GitHub 数字编号，只用来执行「每个账号每个版本一份」；这个编号在对应的 Issue 上本来就是公开的。
  它不会被软件下载，`index.json` 里没有任何账号信息。
- Action 只使用 GitHub 提供的默认 `GITHUB_TOKEN`，不需要任何其他密钥。
